# 豆子库存管理

## Goal

为拼豆工具新增一套账号绑定的豆子库存能力：用户登录后可按已有色卡/套装批量录入每个色号库存；在「拼豆工作间」开始制作前检查库存是否够用，结束制作后按图纸用量扣减，并在库存低于阈值时提示补豆；同时提供独立 Tab「豆子库存」统一查看、调整和管理使用情况。库存以服务端权威数据为准，支持跨设备同步。

## Background / Confirmed Facts

- 当前应用是 Vite + React + TypeScript PWA，主要本地功能包括「拼豆图纸」和「拼豆工作间」。
- 顶层 Tab 当前为 `bead | workshop | xhs`，Tab 切换使用 keep-alive 隐藏策略，见 `src/App.tsx`。
- MARD 291 色色卡、标准/扩展范围、商家套装码表均已存在，见 `src/lib/palettes/`。
- 商家套装已配置 24/48/72/96/120/144/168/192/216/221/264 色，用户提到的 44 色目前未在现有配置中出现。
- 「拼豆图纸」生成后的 `BeadPattern.counts` 已记录每个色号需要的颗数，见 `src/lib/pattern.ts`。
- 「拼豆工作间」识别结果已有 `result.colors[].count`，格点模式来自 `BeadPattern.counts`，像素模式来自识别计数，见 `src/lib/workshop/analyze.ts` 和 `src/features/workshop/BeadWorkshopTab.tsx`。
- 账号体系已存在：D1 `users` / `sessions`、`pd_session` Cookie、`/api/me`、`resolveSessionUser`，见 `migrations/0001_auth_session.sql`、`worker/auth/session.ts`。
- Worker 路由集中在 `worker/index.ts`；业务数据可扩展 D1 migration，现有 migration 为 auth 与 AI 配额配置。
- 本地拼豆/工作间**图纸图片**仍不上传服务器；库存仅同步色号与数量，不上传图纸。

## Confirmed Decisions

| # | Decision | Choice |
|---|----------|--------|
| 1 | 库存持久化 | **云端存储**：绑定登录账号，D1 权威数据，支持跨设备 |
| 2 | 图片隐私边界 | 图纸识别仍本地；仅上传/同步色号数量，不上传图纸文件 |
| 3 | 低库存阈值 | 全局阈值，每用户独立存储，默认 100 颗，可在库存 Tab 调整 |
| 4 | 余额流水 | 每次录入/校正/扣减都写一行 ledger；MVP 提供库存 Tab 内「流水」折叠区展示近期条目；图表分析留后续迭代 |
| 5 | 写入鉴权 | 仅登录即可；邮箱验证仍只拦 AI 图像编辑，不拦截库存写入 |

## Requirements

### Access / Sync

- R0. 使用「豆子库存」录入、校正、开始检查与结束扣减前，用户必须已登录。
- R0.1 未登录时展示引导登录，不静默失败。
- R0.2 库存以服务端余额为准；前端可缓存展示，但提交录入/校正/扣减后以服务端响应刷新。
- R0.3 库存 API 必须校验会话，拒绝未登录与已封禁账号。
- R0.4 库存写入仅需登录会话，不要求邮箱已验证；邮箱验证仍只拦 AI 图像编辑。

### Inventory Entry

- R1. 新增独立顶层 Tab「豆子库存」，用于查看和管理豆子库存。
- R2. 用户录入库存前必须先选择本次录入适用的颜色集合，复用已有色卡配置：完整 291、标准 221、扩展 70、商家套装 24/48/72/96/120/144/168/192/216/221/264 等。
- R3. 录入界面采用表格方式展示色号：系列字母作为行，数字作为列，单元格组合为 `A1`、`A2`、`B1` 等，只展示所选颜色集合中存在的色号。
- R4. 每个色号单元格需显示基础色号信息与当前库存，并允许录入本次新增库存。
- R5. 录入单位支持「颗」和「克」两种；录入克数时按 `1g = 100颗` 换算为库存颗数，最终库存统一以颗为单位保存与计算。
- R6. 用户可以批量提交本次表格录入；提交后库存**增加**到对应色号余额中，而不是覆盖原余额。
- R7. 用户可以在库存管理 Tab 中对单个色号进行手动校正，支持直接设置库存余额为非负整数。

### Inventory Overview

- R8. 「豆子库存」Tab 需要提供统一查看能力，包括总库存颗数、低库存颜色数、已录入颜色数、按色号查看余额。
- R9. 用户可以按色卡集合/系列/低库存状态筛选库存列表或表格。
- R10. 库存界面需明确显示所有数量单位，避免克数与颗数混淆。
- R11. 库存数据在刷新页面、换浏览器/设备登录同一账号后仍可查看。

### Workshop Start / Finish

- R12. 「拼豆工作间」新增「开始」按钮；当已有识别结果时，点击开始需基于**当前服务端库存**计算是否足够完成当前图纸。
- R13. 开始检查需按色号比较 `库存余额 >= 当前图纸所需颗数`，并展示足够/不足结果。
- R14. 若库存不足，需要列出不足色号、当前余额、图纸需要、缺口数量；**仅提醒，不阻止用户开始**。用户可选择继续开始制作。
- R15. 用户确认开始后（无论库存是否足够），工作间进入「进行中」状态，锁定本次图纸用量快照，避免后续重新识别/调分隔线改变扣减依据。
- R16. 「拼豆工作间」新增「结束」按钮；仅当存在进行中的制作时可结束。
- R17. 结束制作时调用服务端按开始时锁定的用量快照扣减库存余额，并结束进行中状态。扣减时余额不够的颜色扣到 `0` 即可，**不允许出现负数**；如有扣减缺口，在结束后提醒用户。
- R18. 结束扣减后，如果某些颜色余额低于阈值，需要提示用户补豆，展示色号、剩余数量和阈值。
- R19. 若进行中期间用户重新上传或重新识别图纸，界面需提示当前制作快照不会自动变化，除非用户结束/取消后重新开始。

### Low Stock Alert

- R20. 系统需要有低库存阈值，用于结束后和库存管理 Tab 中判断补豆提醒；阈值为每用户独立配置，默认 `100` 颗，用户可在库存 Tab 修改。
- R21. 低库存提醒只针对已录入过库存或本次图纸使用过的颜色，避免对全 291 色全部提示补豆。

### Inventory Ledger

- R22. 每次库存变动（批量录入、单色校正、工作间结束扣减）必须同步写入一条流水记录，包含色号、增减数量、变动原因与时间戳。
- R23. 库存 Tab 需提供「流水」折叠区，按时间倒序展示近期流水条目，展示色号、增减数量、原因与时间。
- R24. 流水仅展示与查询，MVP 不支持删除、编辑或导出流水。
- R25. 图表/趋势/Top 消耗色号等分析能力不纳入本 MVP，留待后续迭代。

- [ ] AC2. 库存录入可选择已有色卡/商家套装，表格按行字母 + 列数字组成色号，只展示该集合内存在的色号。
- [ ] AC3. 输入 `1g` 并提交后，对应色号服务端库存增加 `100` 颗；输入颗数时按原数量增加。
- [ ] AC4. 同一账号在刷新或另一设备登录后，可从服务端看到已提交库存。
- [ ] AC5. 未登录访问库存管理或工作间开始/结束时，有明确登录引导；不执行库存写入。
- [ ] AC5.1 已登录但邮箱未验证时，库存录入/校正/扣减/流水/阈值均可正常使用；不出现「请先验证邮箱」拦截。

- [ ] AC8. 结束后若颜色低于阈值，界面列出需要补豆的颜色、剩余数量和阈值。
- [ ] AC9. 进行中时重新识别不会改变本次结束扣减用量，除非用户重新开始。
- [ ] AC10. 所有新增 UI 文案为中文，数量单位清晰标注为「颗」或「g」。
- [ ] AC11. `npm run build` 与 `npm run lint` 通过；现有「拼豆图纸」「拼豆工作间」「小红书下图」、登录会话无明显回归。
- [ ] AC12. 图纸图片仍不上传；库存 API 只传输色号与数量。
- [ ] AC13. 每次库存变动均可在「流水」折叠区看到对应条目（色号、增减、原因、时间）。
- [ ] AC14. 流水条目按时间倒序展示，不支持删除/编辑。

## Out of Scope

- 匿名本地库存作为正式数据源（可后续加离线缓存，但非本 MVP 正式方案）。
- 多用户后台库存管理 / 管理员查看任意用户库存。
- 购买清单、补豆下单链接、价格统计。
- OCR/扫码/导入 Excel 文件。
- 自动推断用户拥有哪个商家套装。
- 对 44 色等当前不存在的套装配置新增真实码表；除非后续提供准确配置。
- 复杂 CRDT / 逐单元格离线冲突合并。
