# 豆子库存 CSV 导入

## Goal

在“豆子库存”页面支持从本地 CSV 批量导入库存，CSV 的二维结构与当前库存表格一致，
让用户可以在电子表格中维护大量色号后一次性同步到自己的账号库存。

## Background / Confirmed Facts

- 当前库存表格以“系列”为行、色号数字后缀为列；单元格对应完整 MARD 色号，例如
  行 `A` 与列 `1` 对应 `A1`。
- 页面当前支持完整 291 色、标准 221 色、扩展 70 色及商家套装范围。
- 当前批量录入接口采用“增加”语义，单位支持颗和克；单色校正接口采用“覆盖”语义。
- 既有库存决策要求服务端余额权威、每次库存变化与流水原子写入；CSV 导入不能绕过该约束。
- 库存由 Cloudflare D1 保存，并由服务端当前 Session 的用户 ID 隔离。
- CSV 应在浏览器本地读取和解析；文件内容不需要上传或保存到服务器，仅解析后的色号与
  数量通过现有同源库存 API 提交。

## Requirements

- R1. 登录用户可从库存页面选择一个 `.csv` 文件导入。
- R2. CSV 使用与界面一致的矩阵格式：首列为系列，首行为数字后缀，每个有效单元格映射
  为一个 MARD 色号及数量。
- R2a. 规范示例为 `系列,1,2,3` 表头与 `A,100,0,` 数据行；数量统一表示“颗”，
  必须是非负整数。
- R3. 解析必须兼容 UTF-8 BOM、Windows/Unix 换行、带引号字段与逗号转义。
- R4. 只接受项目 MARD 色表中存在的色号；空白单元格忽略，非法数字、负数、重复行列或
  无法识别的结构必须向用户报告，不能静默写入错误库存。
- R5. 提交前显示解析摘要，至少包含有效色号数、忽略空格数和错误信息；存在阻断错误时
  不发起库存写入。
- R6. 导入后的写入必须继续使用当前登录用户的库存 API，并刷新库存总览与流水。
- R7. CSV 原文件只在浏览器内解析，不上传、不持久化。
- R8. 导入采用“覆盖非空单元格”语义：CSV 非空数量直接设置为当前余额，空白保持不变，
  `0` 明确清零；导入流水使用 `adjust` 原因并记录实际差值。
- R9. 一次导入必须全量校验后再批量提交，服务端将同一批库存更新与流水原子写入，
  避免部分成功。
- R10. CSV 可包含完整色卡或任意行列子集，不强制匹配当前页面选择的色卡/套装范围；
  但每个非空交叉单元格必须能组成真实 MARD 色号。
- R11. 文件限制为 UTF-8 CSV，最大 1 MiB、最多 291 个非空色号；不新增运行时依赖。

## Acceptance Criteria

- [x] AC1. 可选择合法矩阵 CSV，并正确识别行列交叉形成的完整色号。
- [x] AC2. 支持 UTF-8 BOM、CRLF/LF、CSV 引号和逗号转义。
- [x] AC3. 空白单元格不会改变库存；非法结构或数量会显示中文错误且不会部分写入。
- [x] AC4. 导入结果只写入当前 Session 用户，并返回更新后的库存快照。
- [x] AC5. 导入成功后界面库存总览、明细和流水同步更新。
- [x] AC6. CSV 文件内容不会作为原文件发送到 Worker。
- [x] AC7. `npm run build`、`npm run lint` 以及 CSV 解析回归测试通过。
- [x] AC8. 重复导入同一文件不会叠加库存；空白保持、`0` 清零和非空覆盖行为符合要求。
- [x] AC9. 超大文件、超过 291 个色号、重复行列、未知色号、负数、小数及损坏引号均被拒绝。

## Out of Scope

- Excel `.xlsx` 导入。
- 上传或长期保存原始 CSV 文件。
- 修改 MARD 色表、库存用户隔离或现有克重换算规则。
