# 全站 UI 视觉升级

## Goal

在不改变现有业务能力和核心工作流的前提下，统一并全面提升拼豆助手的视觉设计、信息层级、操作反馈与响应式体验，使生成、工作间、库存、小红书、账号、管理和信息页面呈现为同一套成熟产品。

## Background / Confirmed Facts

- 当前是 Vite + React + TypeScript 单页应用，无组件库、CSS Modules 或 Tailwind。
- 全站样式分散在 `App.css`、`index.css` 与各 feature 的 CSS 中，存在绿色、黑色等多套按钮语言，圆角、间距、边框和状态色不统一。
- 主应用包含拼豆图纸、拼豆工作间、小红书下图、豆子库存四个 tab；另有账号、管理、隐私和关于页面。
- 拼豆、工作间和库存依赖 keep-alive 挂载；视觉升级不得破坏已有状态、Canvas、上传、库存、认证及移动端流程。
- 产品 UI 使用中文；项目不引入重型 UI 依赖，适合以 CSS design tokens 和现有 React 结构渐进升级。

## Requirements

- R1. 建立统一的颜色、字体、间距、圆角、阴影、边框、状态色和交互状态设计体系，并以语义化 CSS tokens 同时支持亮色与暗色主题。
- R2. 升级 App shell、品牌区、主导航、账号区和页脚，使四个工具入口层级清晰。
- R3. 全面统一按钮、输入框、选择器、分段控件、chip、卡片、提示、空状态和 loading/error/success 反馈。
- R4. 优化拼豆生成页三栏工作区，增强参数区、画布区、色板区的层级与可读性。
- R5. 同步升级工作间、库存、小红书、认证、管理、隐私和关于页面，避免局部换肤。
- R6. 桌面端与移动端均需可用；高密度表格、色板和 Canvas 工作区不得因装饰损失有效空间。
- R7. 保持现有业务行为、中文文案语义、隐私约束、无障碍基础和 keep-alive 机制。
- R8. 不新增重型 UI 框架；如需图标或字体，优先使用轻量、可离线或现有能力。
- R9. 采用“温润创作工坊”视觉方向：米白与暖灰作为基础背景，森林绿作为品牌/主操作色，陶土橙作为有限强调色；卡片使用适度圆角、柔和阴影与克制的手作质感。
- R10. 信息密度采用“舒适但紧凑”：品牌区、空状态与信息页适度留白；生成参数、色板、工作间和库存表格保持高效密度，避免为了装饰增加大量滚动。
- R11. 品牌识别采用中等强度：保留并精修四色拼豆方块标记，使用少量点阵/拼豆纹理、清晰标题层级和陶土橙强调；不加入吉祥物或大面积品牌插画。
- R12. 动效采用轻微且功能性的策略：仅为按钮、tab、卡片与状态反馈增加短时过渡；Canvas、高频参数调整和表格滚动保持即时响应，并支持 `prefers-reduced-motion`。
- R13. 主导航暂时保留顶部形态，升级为清晰的工具切换栏；桌面端避免占用三栏工作区宽度，移动端采用紧凑适配。
- R14. 本轮包含完整暗色模式；暗色界面不得改变拼豆色板 swatch、原图和生成画布的真实颜色表达。
- R15. 主题提供“跟随系统（默认）/亮色/暗色”三态切换，入口位于顶部操作区，用户选择保存在本地；跟随系统时响应系统主题变化。

## Acceptance Criteria

- [x] AC1. 全部产品页面在亮色与暗色主题下均采用一致且可识别的视觉语言，不再出现明显割裂的控件风格。
- [x] AC2. 主导航、页面标题、主要操作和次要操作具有清晰层级。
- [x] AC3. 拼豆生成、工作间、库存和小红书核心流程的布局、交互与状态不回归。
- [x] AC4. 登录/注册/验证、管理、隐私和关于页面完成同风格升级。
- [x] AC5. 常见桌面宽度与窄屏移动端无横向页面溢出；必须横向滚动的表格在自身容器内滚动。
- [x] AC6. 键盘焦点、disabled、hover、active、error、success 状态可辨识。
- [x] AC7. `npm run build` 与 `npm run lint` 通过。
- [x] AC8. 首次访问默认跟随系统；手动选择亮色或暗色后刷新仍保留；恢复“跟随系统”后继续响应系统变化。
- [x] AC9. 暗色模式下原图、Canvas 和拼豆色块颜色不被滤镜或主题样式改变。

## Out of Scope

- 改写生成、识别、库存、认证或下载等业务逻辑。
- 引入完整组件库或重构为新的前端框架。
- 新增品牌吉祥物或大面积插画资产。
