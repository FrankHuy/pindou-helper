# 拼豆工作间图纸识别优化

## Goal

优化拼豆工作间的图纸识别流程，引入"先确认色板→再识别图→不确定色聚类交用户决策"的三阶段交互，解决水印 / 杂色导致的误识别问题。

## Background / Confirmed Facts

- 当前识别流程为一次性管线：`analyzeWorkshopImageData` 一次性完成分界线 → 图例采色 → 格点/像素识别 → 输出最终结果，用户无法中途修正色板。
- 图例采色逻辑在 `src/lib/workshop/legend.ts`：`sampleLegendColors`（BFS 连通域找色块）→ `sampleScatteredColors`（散点采样兜底）→ `mineColorsFromPattern`（从图案区挖色三级降级）。
- 格点识别在 `src/lib/workshop/grid.ts`：边缘投影 + 自相关检测格子周期，验证后输出 `BeadPattern`。
- 像素模式在 `src/lib/workshop/pixel.ts`：逐像素 / 2×2 块匹配 palette → `labels`（Int16Array）。
- 空格判定在 `src/lib/workshop/empty.ts`：`isLightBackground`（高亮度低饱和）+ `closestColorWithDistance` 距离阈值 95。
- `BeadWorkshopTab.tsx` 组件当前在上传 / 拖分界线 / 「重新识别」后自动调用 `analyzeWorkshopImageData`，结果不可中途修正。
- 全程共用 `src/lib/color-match.ts` 的 `closestColor`（加权 RGB 距离），无第二套实现。
- 已有库存开始/结束集成（`activeSession` 锁定快照、扣减），本次优化不应破坏该集成。
- MARD 全色卡 291 色（`MARD_COLORS`）每项含 `code`、`hex`、`name`、`series`、`rgb`，可用于色板手动添加 UI。
- 拼豆图纸 Tab 已有系列筛选 + 色号列表 UI 模式（`src/App.tsx`），可参考用于工作间色板确认阶段的手动添加。

## Confirmed Decisions

| # | Decision | Choice |
|---|----------|--------|
| 1 | 识别流程改为三阶段 | **色板确认 → 图案识别 → 不确定色决策** |
| 2 | 色板确认前不进行格点/像素识别 | 确认后用确认色板作为 restricted palette 进行图案识别 |
| 3 | 不确定色聚类展示 | 每个聚类显示代表性色 + 高亮，用户从确认色板中选择归属 |
| 4 | 用户可补充色号到色板 | 在确认阶段允许手动加入 MARD 全色卡中的色号 |
| 5 | 用户可删除色板中的误识别色号 | 在确认阶段可去掉水印 / 杂色对应的色号 |
| 6 | 图纸图片不上传 | 仍然纯本地 Canvas 处理 |
| 7 | 库存开始/结束集成保持兼容 | 新流程不应破坏 activeSession 锁定与扣减 |
| 8 | 聚类算法在纯函数 `src/lib/workshop/` 中实现 | 不引入 OCR / 新依赖 |
| 9 | 不确定色聚类上限 | **K = 10**，取像素数 Top 10 |
| 10 | 图例提取失败时 | 仍从图案区挖色作为「建议色号」展示，标注来源 |
| 11 | Phase 3 可跳过 | 不确定色默认归空格，用户可直接接受 Phase 2 结果 |

## Requirements

### Phase 1: 色板确认

- R1. 上传图片 + 分隔线拖动逻辑保持不变（分界线决定图例区范围）。
- R2. 上传后自动提取图例区色号候选；若图例区未找到色块，则从图案区挖色作为「建议色号」展示，标注来源为图案估色。
- R3. 用户可删除候选色号（误识别 / 水印颜色）。
- R4. 用户可手动补充色号（从 MARD 全 291 色中选择；提供系列筛选 + 色号列表或搜索）。
- R5. 用户点「确认色板」后进入 Phase 2。
- R6. 色板至少保留 1 个色号才可确认；0 个时提示「至少选择一个色号」。

### Phase 2: 图案识别

- R7. 用确认色板作为 restricted palette 执行格点 / 像素识别。
- R8. 格点优先，像素兜底，逻辑与当前 `tryBuildGridPattern` → `buildPixelAssignment` 一致。
- R9. 这一步用户不需要额外操作，识别完成后自动进入 Phase 3。
- R10. 如果确认色板下格点/像素均无法识别（格子太小、覆盖率不够等），展示原始错误提示。

### Phase 3: 不确定色决策

- R11. 识别完成后，计算不确定格子：格子采样 RGB 非背景且到确认色板中所有色号的距离均 > 阈值 → 标记不确定。
- R12. 不确定颜色按 RGB 相似度聚类成 K 组（K ≤ 10），每组取代表性 RGB 与样本数量。
- R13. UI 展示 K 个不确定色聚类芯片（色块 + 像素数），点击高亮对应区域（Canvas 上高亮不确定格子位置）。
- R14. 用户对每个聚类操作：从确认色板 X 中选一个色号归属 → 所有该聚类格子归为该色号；或选「空格」→ 归为 empty。
- R15. 用户完成所有聚类决策后，点「应用矫正」生成最终结果。
- R16. 最终结果保留高亮功能，与现有色号列表交互一致。
- R17. 如果没有不确定色（所有格子都明确匹配确认色板），直接展示结果，跳过 Phase 3。
- R18. 即使有不确定色聚类，用户也可选择跳过 Phase 3；不确定格子默认归为空格，直接生成最终结果。

### 兼容性

- R19. 库存开始/结束功能不受影响：开始按钮基于最终 `result.colors`，结束扣减锁定快照逻辑不变。
- R20. 「重新识别」按钮在新流程中意指重新提取图例色板（回到 Phase 1）。
- R21. 原有的 grid / pixel 预览、缩放、分界线拖动都保留。
- R22. 所有新增 UI 文案为中文；保留「屏幕色仅供参考」声明。
- R23. 图片不上传服务器，仍然纯本地处理。
- R24. 不引入新依赖 / OCR。

- [x] AC8. 无不确定色时直接展示结果；有不确定色时也可跳过（不确定格子归空格）。
- [x] AC9. 库存开始/结束功能正常工作：开始仍基于 result.colors，结束扣减不受影响。

- [x] AC11. 所有新增 UI 文案为中文；保留「屏幕色仅供参考」声明。
- [x] AC12. `npm run build` 与 `npm run lint` 通过；现有拼豆图纸 / 小红书 / 登录功能无明显回归。

## Out of Scope

- 自动去水印（仍由用户在 Phase 1 删色和 Phase 3 决策处理）。
- OCR / 文字识别。
- 不确定色的"自动归属"建议（用户全手动决策）。
- 批量聚类归属操作（逐个聚类决策）。
- 对不确定色补充确认色板之外的新色号（Phase 3 只能从 Phase 1 确认的 X 色中选）。
